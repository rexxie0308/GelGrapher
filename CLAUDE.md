# GelGrapher: notes for Claude Code

Browser app that turns raw gel / blot images (DNA, RNA, SDS-PAGE, native PAGE, Western, Southern, Northern) into publication figures, with densitometry. Based on GelFigure 0.5.0 by poplarity (MIT); keep that attribution in LICENSE, README, the help dialog and the processing log.

## Commands

```bash
npm install                     # Playwright only (the SessionStart hook does this in cloud sessions)
npm run check                   # fast: every js/*.js parses, index.html loads each script once, artifact builds
npm test -- --browser=chromium  # engine self-test (test/test.html) + interface self-test (js/uitest.js), ~60 s
npm run build                   # dist/gelgrapher-artifact.html (single file for the Claude artifact)
```

Run `npm run check` and the Chromium tests before every push. CI (`.github/workflows/ci.yml`) also runs Firefox and WebKit. In cloud sessions do not run `playwright install`; Chromium is preinstalled under `$PLAYWRIGHT_BROWSERS_PATH`, and when the pinned Playwright is newer than that browser, `tests/run.mjs` falls back to `$PLAYWRIGHT_BROWSERS_PATH/chromium` (or `$PLAYWRIGHT_CHROMIUM_EXECUTABLE`).

## Architecture

Plain scripts on `window` (no modules, no bundler, no dependencies), loaded in this order by `index.html`:
`tiff → ladders → gels → engine → render → quant → zip → pdf → pptx → host → export → demo → app → splitters → editor → ui → figedit → quantui → claude → tour → pwa`.

`splitters.js` drives the three dividers (`.gutter`): they set `--panel-w` on `#app`, `--raw-flex` / `--fig-flex` on `#stage` and `--fig-top` / `--fig-bot` on `#figCol`, remembered in the prefs (`panelW`, `stageSplit`, `figSplit`), and fire `resize`; the editor refits to the crop when a drag ends.

`pwa.js` (marked `data-artifact="no"`, so the artifact build leaves it out) registers `sw.js`, the service worker that stores the app shell for offline use and offers "Reload" when a deployment with a new stamp is found; it runs only over http(s) outside the artifact, and on localhost only with `?pwa=1`. `sw.js` lists every file of the shell (`tools/check.mjs` compares it with `index.html` and `manifest.webmanifest`); the Pages and release workflows replace `__VERSION__` in it. The offline and update behaviour is tested in `tests/run.mjs` (it needs a fresh browser context and `setOffline`), not in `js/uitest.js`; it is skipped in WebKit, whose Playwright build has no service workers.

- `app.js` owns the state `App.S` (JSON-serialisable; undo history is snapshots of it). Coordinates of lanes, bands, arrows, strips and band boxes are in rotated-image pixels, so cropping never moves annotations. `App.src0` is the image as decoded and `App.src` is it flipped as `S.flip` says (`App.applyFlip`, called from `ensureRot`, so undo / redo / project loads re-derive it); `App.flip(axis)` mirrors every annotation in the rotated frame and negates the rotation. `App.selLane` is an accessor: assigning it makes that lane the whole selection, `App.selLanes` (a Set) holds every selected lane and `App.selectLanes(list, primary)` sets several; `App.spreadBetween(i, j)` spaces the lanes between two; `App.yForSize` / `App.parseSize` / `App.arrowToSize` place an arrow at a typed size. New state fields need a default in `startFrom` and in `normalize()` (old projects / GelFigure files lack them), must be carried in `setRotation` and mirrored in `App.flip`, and lane indices must be remapped in `replaceLanes` / `removeLane` / `reorderLanes` / `fixIndices`.
- The working frame is `App.frameMatrix(S)` = `S.keystone.H` (a 3 × 3 homography in the rotated frame, or identity) × the rotation; `App.ensureRot` resamples the source once through it (`E.warp`), `App.frameKey` keys the caches, `App.carryFrame(T)` moves every annotation by a 3 × 3 point map (rotation changes conjugate `H` and carry by the rotation; `App.setKeystone(next)` carries by `H1·H0⁻¹`). `App.autoKeystone` = `E.laneLines` (per-lane centroid lines in 12 horizontal bands) → `E.vanishing` (slope-vs-position regression, significant at 3 σ and ≥ 0.5 % spacing change, at least five lines, never trimmed: inconsistent lanes mean *no* keystone) + `App.bandRowVanishing` (ladder bands across ≥ 2 markers) → `E.keystoneH(V, U, centre)` (line at infinity through the two vanishing points, affine part makes lanes vertical and bands horizontal, unit scale at the centre), repeated on the corrected image; `App.setKeystoneManual(lanesPct, bandsPct)` builds a symmetric keystone; `E.keystoneReport` gives the percentages shown in the panel, the legend (`G.Export.keystoneText`), the log and the methods text. Off by default.
- A gel with several rows of wells keeps `S.gelRows` (y ranges), `S.gelRow` (the row shown) and `S.rowStash` (the other rows' `ROW_KEYS` state); `App.setGelRow` swaps them. `setRotation` and `App.flip` carry the stash too; `E.autoCrop(img, bright, band)` restricts the crop to one row.
- `gels.js` defines experiment types (`kind` = dna | rna | protein | native picks the ladder library and unit). `App.kind()`, `App.baseUnit()`, `App.fmtSize()` / `App.fmtExact()` format sizes; never hard-code "bp".
- `engine.js` is pure image analysis (deskew, autoCrop, lane lattice, ladder fit in log(size)). Changes there affect every gel type: check the synthetic gels (`G.Demo.makeGel({preset: 'dna' | 'sds' | 'western'})`) and run the full tests. Lanes: `presenceProfile` (per-row small opening, top-hat, sqrt; per column top-3 % mean + 75th + 50th percentile, `.band` = top-3 % minus median) → `combPitch` (teeth minus mid-teeth over the crop, minus unexplained peaks) → `detectLanes(img, bright, refW, region)` (every tooth from the first to the last with a lane, centroid-refined; `refW` = the crop width so a gel small in a large frame is analysed at its own scale) → `detectLaneLattice` (slab edges by the first step down to the background outward from the loaded lanes, well template validated by the loaded lanes' agreement, extension outward while a tooth has a bump of band evidence or a well, never in the 0.75-pitch margin). `node tools/lane-bench.mjs` scores it on the synthetic gels; `--raw file WxH` adds an 8-bit grey image (the user's photographed SDS-PAGE with three ladders, a torn corner and keystone is the sanity check: 13 wells). `node tools/marker-bench.mjs` reports which lane `App.autoMarkers` takes for the ladder on 19 synthetic variants (crowded lysates, mirrored, faint ladder): run it before changing that rule or the lane lattice. GelFigure 0.6.1's explained-fraction score was tried there (2026-10) and tied with the band-count / band-strength rule on every variant once the remembered ladder was reset between gels, so the rule stayed; the three misses are 90-band lysate gels where the lattice itself loses lanes.
- `editor.js` draws two overlay layers for strips and band boxes; only the layer of the open view (`G.QuantUI.view()`: strips with `figure`, boxes with `quant`) is hit-tested and drawn in front, the other is a faint outline. The view follows the panel: `G.QuantUI.follow(v)` switches (with a flash on the segment) when a control of step 6 (`#quantSec`) or of steps 1–5 is pressed or focused (capture listeners on `#sections`; closing a fold never switches), and `figedit.setMode` calls it for every tool.
- `render.js` builds the figure SVG in points (`composeGel` handles removed lanes and stacked strips; `mapY` maps crop rows to figure rows or null outside strips). Group labels: `fitLabel` applies `style.groupFit` (`wrap` = balanced `wrapLines`, `shrink` down to `MIN_PT`, `line`) after typed `\n` breaks, one `<text>` per line so `pdf.js` needs no change; `groupTiers` stacks by extent in points; `build` returns `minPt` for the pre-flight check. Typefaces are the `FONTS` allowlist (Arial, Helvetica, Times New Roman): `build` calls `setFont(style.font)`, `measure` and the SVG root follow it, `pdf.js` reads `G.Render.font()` to pick Helvetica or Times. `style.labelAngle` is `'auto'` or 0–90 (`G.Render.labelAngle` clamps). `export.js` `rasterSize` / `rasterLimit` check a raster export against the canvas limit (Safari and iOS 16.7 MP) before drawing; `svgToGray` renders the SVG in bands for TIFF. `pptx.js` (`G.PPTX.fromFigure(svg, {crop, gel})`) walks the same SVG vocabulary as `pdf.js` into one slide: text boxes, connectors, custom-geometry arrow heads, and one `p:pic` per lane segment × strip with an `a:srcRect` crop of the whole processed crop (`App._lastCrop`, `App._lastGel` from `buildFigure`). `tiff.js` decodes palette and 1/2/4-bit TIFFs through `paletteLut` and returns `.warnings` that `ui.js` toasts on load.
- `quant.js` is densitometry on raw pixels (never the display levels) and the band-size table (`S.quant.mode`: `'band'` counts only pixels above the noise floor, box-size independent; `'box'` sums the whole box; `measure()` gives `refOk` per box and `chartSVG` falls back to the values themselves when a reference lane lacks the band); `quantui.js` drives the two windows of the right column: `#figPane` (figure) and `#quantView` (analysis: chart, table, lane profile, band sizes), stacked with the `#gutterFig` divider (`splitters.js`, pref `figSplit`). `G.QuantUI.show(pane, on)` opens or closes one, `setView(v)` makes it the active window (opening it), `view()` is the active one (it decides the editor's overlay layer), `isShown(pane)`; `#viewSeg` in the top bar toggles each; `#paneEmpty` appears when both are closed. `follow(v)` activates the window a panel control belongs to (`.ana-sec` = step 6). `S.quant.norm` ('control' | 'lane' | 'none') and `S.quant.plot` (type, values, refLine, title, ylabel) are state; `G.Quant.methodsText` writes the methods paragraph. `ui.js`: `#btnFigExport` / `#figFmt` export the figure alone, `#btnQChart` the chart, the green `#btnPNG` runs `exportPackage` (`G.Export.packageBlob`, one ZIP). A new band box opens the analysis window; a load opens it only when the gel has boxes.
- `tour.js` is the guidance engine: `G.Tour.start('tutorial')` is the hands-on tutorial (each step has parts with an `enter` baseline and a `done(base)` predicate checked on every App event and every 500 ms, never satisfied while `#floatEd`, `#popover`, a `.dlg` or `#busy` is open, and re-checked 900 ms later before the hand-over; `watch` lists the areas kept lit by the SVG dim `#tourDim` and avoided by the card; `panel` opens the folds around the target once on entry, never the fold whose summary is the target; the overlay lets clicks through; `text` may be a function worded for `App.kind()`) and `G.Tour.start('tour')` the read-only overview. `ui.js` `startup` opens the empty workspace (or the library) and starts the tutorial once (`tutorialSeen` pref); the tour is remembered in `tourSeen`. Steps whose target is off screen are skipped.
- `host.js` is the only place that touches `window.claude` (Claude artifact runtime). Everything must work without it.
- The library (`App.library` in `app.js`: `list` / `open` / `rename` / `remove` / `clear`) keeps every opened gel in IndexedDB: store `gels` has one small record per image (state snapshot, thumbnail, title, names; key = the image's SHA-256), store `blobs` the file bytes once per image and per marker image. `App.saveDraftSoon` (called by `commit` / `undo` / `redo`) saves 800 ms after a change; examples are never saved, and a gel removed while open stays out (`App._libSkip`) until it is loaded again. `App.close()` saves a due draft, clears the state and emits `closed`; `ui.js` then shows the start screen. `library.remove` / `clear` close the open gel. `ui.js` renders the cards on the start screen (`#libBox`) and in the Library dialog (`#libDlg`). Self-tests 19 and 32 need IndexedDB (`?draft=1`).

## Conventions

- The interface, figures, legends, logs and exported files are English only; there is no translation layer.
- No `alert` / `confirm` / `prompt` / `window.print` (inert in the artifact; `tools/build-artifact.mjs` fails the build on them). Use `G.UI.alert`, `G.UI.confirm` (async, in-page) and `G.Export.download` (resolves 'saved' | 'declined' | 'failed').
- Image integrity: linear whole-image adjustments only by default; anything that changes how data looks or what is shown (inversion, gamma, removed lanes, strips, marker image, densitometry method) is reported in `G.Export.legendHints` and the processing log.
- Colours in CSS are tokens on `:root` with dark values under `prefers-color-scheme` and `[data-theme]`; the values are the Paper Radar palette (teal accent, amber warn, green ok) so the owner's artifacts match. The figure itself is always black on white, and the overlay colours on the raw image (red crop, blue lanes, yellow marker, teal strips, green band boxes) are functional, not theme colours.
- Ladder additions need a manufacturer datasheet (see CONTRIBUTING.md).
- New behaviour gets a check in `js/uitest.js` (sections 20+) and an assertion in `tests/run.mjs`.

## Claude artifact

The app is published as a Claude artifact at https://claude.ai/artifact/TaJkMEbS7d2Yf81LcVr2oj (pinned in the owner's sidebar) with capabilities `{"downloads": true, "sample": {}}`.

To update it after changing the app: `npm run build`, then publish `dist/gelgrapher-artifact.html` to that URL with the Artifact tool (pass the URL as `url` from a new conversation; omit `capabilities` to keep them, omit `icon`). Things that differ inside the artifact viewer:

- downloads go through `claude.use('downloads').save()`, which only accepts png, jpg, gif, webp, svg, pdf, csv, json, txt, md, html, xlsx, docx, pptx, zip; `G.Export.download` wraps anything else (TIFF, `.gelfig`, original data) in a ZIP, and the app opens such ZIPs;
- `sample` powers "Draft legend and methods with Claude" (`js/claude.js`); it sends only a text summary, never the image;
- no query string reaches the page, so the `?demo=1` / `?uitest=1` test hooks only work on a normal server.
