# GelGrapher: notes for Claude Code

Browser app that turns raw gel / blot images (DNA, RNA, SDS-PAGE, native PAGE, Western, Southern, Northern) into publication figures, with densitometry. Based on GelFigure 0.5.0 by poplarity (MIT); keep that attribution in LICENSE, README, the help dialog and the processing log.

## Commands

```bash
npm install                     # Playwright only (the SessionStart hook does this in cloud sessions)
npm run check                   # fast: every js/*.js parses, index.html loads each script once, artifact builds
npm test -- --browser=chromium  # engine self-test (test/test.html) + interface self-test (js/uitest.js), ~60 s
npm run build                   # dist/gelgrapher-artifact.html (single file for the Claude artifact)
```

Run `npm run check` and the Chromium tests before every push. CI (`.github/workflows/ci.yml`) also runs Firefox and WebKit. In cloud sessions do not run `playwright install`; Chromium is preinstalled under `$PLAYWRIGHT_BROWSERS_PATH`, and when the pinned Playwright is newer than that browser, `tests/run.mjs` falls back to `$PLAYWRIGHT_BROWSERS_PATH/chromium` (or `$PLAYWRIGHT_CHROMIUM_EXECUTABLE`).

## Architecture

Plain scripts on `window` (no modules, no bundler, no dependencies), loaded in this order by `index.html`:
`tiff → ladders → gels → engine → render → quant → zip → pdf → pptx → host → export → demo → app → splitters → editor → ui → figedit → quantui → claude → tour → pwa`.

`splitters.js` drives the three dividers (`.gutter`): they set `--panel-w` on `#app`, `--raw-flex` / `--fig-flex` on `#stage` and `--fig-top` / `--fig-bot` on `#figCol`, remembered in the prefs (`panelW`, `stageSplit`, `figSplit`), and fire `resize`; the editor refits to the crop when a drag ends.

`pwa.js` (marked `data-artifact="no"`, so the artifact build leaves it out) registers `sw.js`, the service worker that stores the app shell for offline use and offers "Reload" when a deployment with a new stamp is found; it runs only over http(s) outside the artifact, and on localhost only with `?pwa=1`. `sw.js` lists every file of the shell (`tools/check.mjs` compares it with `index.html` and `manifest.webmanifest`); the Pages and release workflows replace `__VERSION__` in it. The offline and update behaviour is tested in `tests/run.mjs` (it needs a fresh browser context and `setOffline`), not in `js/uitest.js`; it is skipped in WebKit, whose Playwright build has no service workers.

- `app.js` owns the state `App.S` (JSON-serialisable; undo history is snapshots of it). Coordinates of lanes, bands, arrows, strips and band boxes are in rotated-image pixels, so cropping never moves annotations. `App.src0` is the image as decoded and `App.src` is it flipped as `S.flip` says (`App.applyFlip`, called from `ensureRot`, so undo / redo / project loads re-derive it); `App.flip(axis)` mirrors every annotation in the rotated frame and negates the rotation. `App.selLane` is an accessor: assigning it makes that lane the whole selection, `App.selLanes` (a Set) holds every selected lane and `App.selectLanes(list, primary)` sets several; `App.spreadBetween(i, j)` spaces the lanes between two; `App.yForSize` / `App.parseSize` / `App.arrowToSize` place an arrow at a typed size. New state fields need a default in `startFrom` and in `normalize()` (old projects / GelFigure files lack them), must be carried in `setRotation` and mirrored in `App.flip`, and lane indices must be remapped in `replaceLanes` / `removeLane` / `reorderLanes` / `fixIndices`.
- The working frame is the source rotated by `S.rotation` and, when `S.geom` is set, sent through `S.geom.grid` (`E.Grid`: nx × ny nodes over the canvas holding the rotated-frame source coordinate of each output node; keystone, per-lane straightening or both composed), resampled once by `E.warpGrid(src, grid, R⁻¹)` in `App.ensureRot`; `App.frameKey` keys the caches; `App.carryFrame(T)` moves every annotation by a 3 × 3 matrix or a point function (the crop by the midpoints of its four sides, so a keystone spreads it with the lanes; `App.reframeCrop()` then puts each side in the gap beside the outer lane it holds, called at the end of `autoGeometry`) (a rotation change conjugates the grid with `E.Grid.conjugate` and carries by the rotation; `App.setGeom(next)` carries by `Grid.inv(new) ∘ Grid.at(old)`). `App.autoGeometry` (async; run by `autoAll` at load and by the Auto button; yields after every step with `App.progress` text): first the slab outline (`E.slabQuad(img, {x, y, win})` → `E.homographyFromQuad`), kept only when `E.vanishing` on the re-detected lanes shows them straighter than before; then the keystone from `E.laneComb` (all lanes fitted together as one equally spaced family per horizontal band, 32 bands (`COMB_BANDS`), the first family of a band robust (median pitch over pairs of teeth), tracked from the middle outward, rows above `cropMeta.wellY + 2.5 P` left out (`yMin`: the well walls sit between the lanes and deep pockets compress the spacing); the pitch's change with height, by a line weighted by each band's tooth spread, gives the vanishing point; a lane drifting off the family by > 0.15 P and 3 se is excluded (`excluded`, ≤ 2), a band far off the line dropped (`dropped`), `chi2` = lack of fit; `sigma` = the significance required, 3 in every round, and every round must move the far lane by ≥ 0.1 pitch) + `App.bandRows` rows across ≥ 2 well-fitting markers → `E.keystoneH` → `Grid.fromH`, iterated to convergence (≤ 4 rounds while the residual is significant, keeps its sign and shrinks; lanes detected again between rounds; `App.autoGeometry.onStep(label)` is called after every step for probes); then, once, `E.laneTraces` (`E.trackLane`: a Viterbi chain of band candidates per lane under a keep-your-direction prior, smoothed, piecewise linear, held beyond its bands; chains with jitter > 0.1 pitch are not trusted) + ladder band rows → `E.straightenGrid`, applied only when the median bend over trusted lanes exceeds max(3 px, 5 % pitch) and reverted when the median does not fall or the lane contrast (`App.laneContrast`: valley / peak of the column density at the lanes) does not improve (shift interpolated between lanes, held beyond, faded outside the crop; a round shifting more than a pitch is rejected); `App.autoLanes` between rounds, `App.relaneMarkers` at the end. `App.setGeomCorners(quad)` (Manual) = `E.homographyFromQuad` → grid; the editor draws the box (corner and side handles, every other overlay hidden) while `G.Editor.setCorners(true)`, a drag only updates `App.pendingCorners`, and `ui.js` applies it with the Apply button (`G.UI_placing()` says whether the box is being placed); `App.onCropDone` (crop drag end, 350 ms after release) re-detects the lanes in the box unless a lane in it is `manual` (placed by hand: `addLane`, a dragged lane line, `evenLanesInCrop`, `spreadBetween`); Off calls `App.redetectAll` (lanes in the crop + markers, chosen ladders kept). `App.setBright(b)` overrides the detection polarity and runs `autoAll(false)`. The ladder search runs once per load, inside `autoGeometry` after the keystone rounds (`autoAll` skips it when the geometry runs), and once more cheaply after a straightening (`relaneMarkers` makes the ladder in use the usual one). The vertical levelling (`App.bandRows`) needs three well-fitting markers, straight rows with scatter ≤ 0.3 of the local row spacing, and the shift is capped at 0.3 of the row spacing (`straightenGrid.maxDy`, disclosed as `geom.dyPx`); the straightening grid has nodes closer than P/2 (≤ 129 × 65), fades within `App.rowBand(S.gelRow)` when the gel has several rows, and is rejected when it folds or scales a cell by > 25 %. `App.geomReport` / `G.Export.keystoneText` feed the panel note, legend, log and methods. `S.geom` is JSON (grid pts), carried through undo and project files; `normalize` drops the old `S.keystone`.

- A gel with several rows of wells keeps `S.gelRows` (y ranges), `S.gelRow` (the row shown) and `S.rowStash` (the other rows' `ROW_KEYS` state); `App.setGelRow` swaps them. `setRotation` and `App.flip` carry the stash too; `E.autoCrop(img, bright, band)` restricts the crop to one row.
- `gels.js` defines experiment types (`kind` = dna | rna | protein | native picks the ladder library and unit). `App.kind()`, `App.baseUnit()`, `App.fmtSize()` / `App.fmtExact()` format sizes; never hard-code "bp".
- `engine.js` is pure image analysis (deskew, autoCrop, lane lattice, ladder fit in log(size)). `E.autoCrop` is coarse to fine: one pass over the frame at 700 px, then, when the box is small against the frame, passes on the window around the box (half its larger side beyond it) until the window settles (≤ 3; a box ≥ 60 % of the frame is tried once inside itself for a gel on a light box; `autoCrop.passes` records them). `App.autoAll(fresh)` re-frames the box on the loaded lanes after the geometry and its rows on the bands, then runs `autoMarkers` once more on the framed box and takes its ladder when it fits the lanes better, or as well with a larger share of its bands matched (the wide box's pocket outlines let a list with one band too many win; a ladder in a torn corner is found on the tight box), else only adds its lanes (`App.reframeCropRows`: 0.6 P beyond the highest and lowest band over lanes with a run of ≥ 3 candidates; candidates = ladder bands on a lane-local peak + clear lane peaks, `App.laneLocalPeaks` = `detectBands` minus peaks that are not ≥ 2 × the lower quartile over all gaps at that row (once that exceeds a sixth of the lane's strongest; the pocket outline on the photograph is 0.8–1.4 ×, real bands ≥ 2.7 ×) and, with several marker lanes, ladder bands on a lane-local peak in fewer than two of them and minus an isolated topmost clear peak; isolated ends dropped (any strength at the top, weak at the bottom); `lanePeaks` / `markerPeaks` stay plain `detectBands`; `E.sharpBandCount` counts against the third-strongest peak and `autoMarkers` takes only lanes with a peak ≥ 0.1 × the gel's strongest); a keystone round that does not reduce the convergence is reverted. Changes there affect every gel type: check the synthetic gels (`G.Demo.makeGel({preset: 'dna' | 'sds' | 'western'})`) and run the full tests. "Comb" in the engine always means the lattice of lane positions, never the loading comb; the auto crop's `wellY` is the row through the well pockets (found by their dark walls), used only as lane evidence (pocket between two walls) and left out of the geometry. Lanes: `presenceProfile` (per-row small opening, top-hat, sqrt; per column top-3 % mean + 75th + 50th percentile, `.band` = top-3 % minus median) → `combPitch` (teeth minus mid-teeth over the crop, minus unexplained peaks) → `detectLanes(img, bright, refW, region)` (every tooth from the first to the last with a lane, centroid-refined; a comb at half the pitch, whose teeth alternate strong and weak, is doubled; `refW` = the crop width so a gel small in a large frame is analysed at its own scale) → `detectLaneLattice` (slab edges by the first step down to the background outward from the loaded lanes, well template validated by the loaded lanes' agreement, extension outward while a tooth has a bump of band evidence or a well, never in the 0.75-pitch margin). `detectLanes` sets its scale again from the pitch when the first profile's top-hat was narrower than the lanes it found (a strip of two or three lanes; the centroid of a lane is taken over its own half-prominence run), and a tooth in the slab margin is a loaded lane only when clearly so. `node tools/lane-bench.mjs` scores it on the synthetic gels (12 gels plus four two- and three-lane strips); `--raw file WxH` adds an 8-bit grey image (the user's photographed SDS-PAGE with three ladders, a torn corner and keystone is the sanity check: 13 wells). `node tools/real-bench.mjs [labels.json]` loads the user's own images in Chromium through `App.load` and compares lanes, ladder wells and keystone with the labels (`docs/benchmark.md`; `bench/real/` is gitignored). `node tools/marker-bench.mjs` reports which lane `App.autoMarkers` takes for the ladder on 19 synthetic variants (crowded lysates, mirrored, faint ladder): run it before changing that rule or the lane lattice. GelFigure 0.6.1's explained-fraction score was tried there (2026-10) and tied with the band-count / band-strength rule on every variant once the remembered ladder was reset between gels, so the rule stayed. Marker lanes (`App.autoMarkers`): one ladder per gel: the usual ladders name the ladder when one fits a lane ≥ 0.7 (when that fit is < 0.97, or leaves a band outside the box, the whole library is tried fairly, without the usual ladders' bonus, on the three best lanes, and a ladder fitting ≥ 0.95 with ≥ 0.9 of its own bands matched takes over when 0.05 more ladder-like or tied with a larger matched share; `App.ladderNotice` tells the user; a single marker lane keeps the usual ladder unless it clearly misfits), else the ladder with the most clear fits (> 0.45) across the candidate lanes does, other lanes stay only when they fit that ladder ≥ 0.8 of the best, and after matching a marker scoring < 0.45 beside one ≥ 0.7 is dropped. `E.jointLadders` scores each lane's shortlist of seven with the full chain assignment (the fast score saturates at 1 for every list about as long as the lane's peaks) and breaks ties by the share of the ladder's own bands matched. Every ladder was checked against its maker's datasheet on 2026-10-29 (`docs/ladder-sources.md`; NEB's from the owner's images, since neb.com refuses automated readers; NEB entries carry NEB's product names). NEB protein ids: `nebp7719s` (Color Prestained 10-250), `nebp7718b` (Blue Prestained 11-250), `nebp7717u` (Unstained 10-200), `nebp7703` (Protein Ladder 10-250), `nebp7712` (Color Prestained 11-245); `ALIAS` in `ladders.js` maps the earlier ids (`nebp7718`, `nebp7717`, `nebp7719`) to the lists they carried so saved projects open. A ladder sold in several loading formats (NEB plain / Quick-Load / Quick-Load Purple / TriDye / Safe Stains) has one entry per format sharing one list constant; `E.uniqueLadders` makes identical lists one candidate in `jointLadders` / `rankLadders` (a favourite stands for them, else the first listed). Interface test 52 checks the library's shape.
- `editor.js` draws two overlay layers for strips and band boxes; only the editing layer (`G.QuantUI.layer()`: 'figure' = lanes, ladder bands, strips; 'quant' = band boxes) is hit-tested and drawn in front, the other is a faint outline. The layer is explicit: the `#editSeg` switch above the image, or a tool that makes a box or a strip (`figedit.setMode('quant' | 'strip')` calls `G.QuantUI.setLayer`); window visibility and the active window never change it. The active window follows the panel: `G.QuantUI.follow(v)` switches (with a flash on the segment) when a control of step 6 (`#quantSec`) or of steps 1–5 is pressed or focused. `G.Editor.setOriginal(on)` shows `App.originalCanvas()` (the decoded image, no flip / rotation / geometry, no overlay, no hit); `App.workingText()` says what the working image is (`#workNote`). Step states (`ui.js updateStatus`): 'done' (tick), 'review' (amber "!": clipped / unknown saturation / colour image; ladder unconfirmed or fit < 0.6) or to do. Markers carry `confirmed` (the Confirm control; a ladder change resets it; legend and log state it); `App.markerSummary(m)` gives the card's matched count, calibrated range, unassigned peaks and `E.ladderCandidates` alternatives. `App.estimateInfo(y, x)` interpolates log size in x between the two nearest ladder lanes (`how`: 'interpolated' | 'nearest' | 'mean'); arrows keep `x`. Lanes carry `role` ('neg') and `noMeasure`; the lane table shows role, Fig. and Meas. The export dialog (`#exportDlg`, `G.UI.openExport(card)`) holds the figure, results package (`btnPNG`), complete archive (`btnArchive`: `packageBlob(..., {archive})` adds original/, the .gelfig and a README) and chart. `App.saveState` / the 'saved' event feed `#saveNote`. The analysis window has Profile / Table / Plot / Band sizes views (`setTab`); the profile is zoomed on the chosen box with the subtracted background and the counted signal.
- `render.js` builds the figure SVG in points (`composeGel` handles removed lanes and stacked strips; `mapY` maps crop rows to figure rows or null outside strips). Group labels: `fitLabel` applies `style.groupFit` (`wrap` = balanced `wrapLines`, `shrink` down to `MIN_PT`, `line`) after typed `\n` breaks, one `<text>` per line so `pdf.js` needs no change; `groupTiers` stacks by extent in points; `build` returns `minPt` for the pre-flight check. Typefaces are the `FONTS` allowlist (Arial, Helvetica, Times New Roman): `build` calls `setFont(style.font)`, `measure` and the SVG root follow it, `pdf.js` reads `G.Render.font()` to pick Helvetica or Times. `style.labelAngle` is `'auto'` or 0–90 (`G.Render.labelAngle` clamps). `export.js` `rasterSize` / `rasterLimit` check a raster export against the canvas limit (Safari and iOS 16.7 MP) before drawing; `svgToGray` renders the SVG in bands for TIFF. `pptx.js` (`G.PPTX.fromFigure(svg, {crop, gel})`) walks the same SVG vocabulary as `pdf.js` into one slide: text boxes, connectors, custom-geometry arrow heads, and one `p:pic` per lane segment × strip with an `a:srcRect` crop of the whole processed crop (`App._lastCrop`, `App._lastGel` from `buildFigure`). `tiff.js` decodes palette and 1/2/4-bit TIFFs through `paletteLut` and returns `.warnings` that `ui.js` toasts on load, plus `fmt` (3 = float), `colour` (an RGB image whose channels differ: warned, converted by luminance) and, for browser-decoded images, `lossy` (JPEG). Saturation: `App.setAcq(img)` → `App.acq = E.clipLevels(...)` (hi / lo: 'limit' at the file's digital limit, 'pileup' when the extreme value is shared by ≥ max(20, 1e-4 n) pixels, e.g. 12-bit in 16-bit: `effBits`; float has no limit). `App.satPredicate()` tests an ORIGINAL value at the band end (top for bright bands, bottom for dark) at that level (null = cannot tell); `App.updateSaturation` counts it over the crop through `App.readRegion`; `App.satReport()` words it ('clipped' | 'probable' | 'none' | 'unknown', always noting that detector saturation is not recorded in a file). The marker image goes through the blot's transform (`ensureMarkerRot` = `warpGrid` / `warp` with the same grid and rotation, keyed by `frameKey`); `E.alignmentShift(a, b)` (gradient NCC, coarse to fine) gives `App.markerAlign` / `App.exposureShift`, worded by `App.alignText`.
- `quant.js` is densitometry on the original pixels: `measureBox` reads rows from `App.readRegion()` → `App.sourceRegion()` (null when the working frame is the source; otherwise each box outline is mapped back through `Grid.at` and the inverse rotation in 32-row chunks and every source pixel whose centre is inside it is read once, never resampled) and the band-size table. `S.quant.mode`: `'box'` (default, linear) sums the whole box after background; `'band'` ("thresholded signal") counts only pixels above 3 sd + 0.004 and is not linear for faint bands (kept for continuity). Every cell has `sd` (edge-row noise around each row's mean), `lod` / `loq` = 3 / 10 · sd·√(n + n²/m) (m = pixels behind its background; rolling counts 4 rows); `measure()` returns `flags[k][j]` = {sat, below: 'lod'|'loq'|null, den: 'sat'|'weak'|null}; a divisor below its LOQ or clipped gives no normalized value; `refOk` needs the reference lane's cell ≥ LOQ and unclipped. `S.quant.norm` 'none' (default) | 'control' (chosen by ticking "Divide by this box"; no box is suggested) | 'lane' (`laneTotal`: the image is a total-protein stain). The analysis area `S.quant.region` (set from the crop by `App.finishRegion` with the first box; `G.Quant.region(S)`) and `lane.noMeasure` decide the analysed lanes (`quantLanes`); `lane.hidden` (figure) never does. `region` is carried in `carryFrame` and `App.flip`; `normalize` gives old projects region = crop and noMeasure = hidden. `G.Quant.describe(App, R)` is the one wording used by the analysis note, CSV, methods, legend, log and the Claude summary. `tools/quant-bench.mjs` measures linearity and box sensitivity; `chartSVG` draws below-LOQ bars dashed; `quantui.js` drives the two windows of the right column: `#figPane` (figure) and `#quantView` (analysis: chart, table, lane profile, band sizes), stacked with the `#gutterFig` divider (`splitters.js`, pref `figSplit`). `G.QuantUI.show(pane, on)` opens or closes one, `setView(v)` makes it the active window (opening it), `view()` is the active one (it decides the editor's overlay layer), `isShown(pane)`; `#viewSeg` in the top bar toggles each; `#paneEmpty` appears when both are closed. `follow(v)` activates the window a panel control belongs to (`.ana-sec` = step 6). `S.quant.norm` ('control' | 'lane' | 'none') and `S.quant.plot` (type, values, refLine, title, ylabel) are state; `G.Quant.methodsText` writes the methods paragraph. `ui.js`: `#btnFigExport` / `#figFmt` export the figure alone, `#btnQChart` the chart, the green `#btnPNG` runs `exportPackage` (`G.Export.packageBlob`, one ZIP). A new band box opens the analysis window; a load opens it only when the gel has boxes.
- `tour.js` is the guidance engine: `G.Tour.start('tutorial')` is the hands-on tutorial (each step has parts with an `enter` baseline and a `done(base)` predicate checked on every App event and every 500 ms, never satisfied while `#floatEd`, `#popover`, a `.dlg` or `#busy` is open, and re-checked 900 ms later before the hand-over; `watch` lists the areas kept lit by the SVG dim `#tourDim` and avoided by the card; `panel` opens the folds around the target once on entry, never the fold whose summary is the target; the overlay lets clicks through; `text` may be a function worded for `App.kind()`) and `G.Tour.start('tour')` the read-only overview. `ui.js` `startup` opens the empty workspace (or the library) and starts the tutorial once (`tutorialSeen` pref); the tour is remembered in `tourSeen`. Steps whose target is off screen are skipped.
- `host.js` is the only place that touches `window.claude` (Claude artifact runtime). Everything must work without it.
- The library (`App.library` in `app.js`: `list` / `open` / `rename` / `remove` / `clear`) keeps every opened gel in IndexedDB: store `gels` has one small record per image (state snapshot, thumbnail, title, names; key = the image's SHA-256), store `blobs` the file bytes once per image and per marker image. `App.saveDraftSoon` (called by `commit` / `undo` / `redo`) saves 800 ms after a change; examples are never saved, and a gel removed while open stays out (`App._libSkip`) until it is loaded again. `App.close()` saves a due draft, clears the state and emits `closed`; `ui.js` then shows the start screen. `library.remove` / `clear` close the open gel. `ui.js` renders the cards on the start screen (`#libBox`) and in the Library dialog (`#libDlg`). Self-tests 19 and 32 need IndexedDB (`?draft=1`).

## Conventions

- The interface, figures, legends, logs and exported files are English only; there is no translation layer.
- No `alert` / `confirm` / `prompt` / `window.print` (inert in the artifact; `tools/build-artifact.mjs` fails the build on them). Use `G.UI.alert`, `G.UI.confirm` (async, in-page) and `G.Export.download` (resolves 'saved' | 'declined' | 'failed').
- Image integrity: linear whole-image adjustments only by default; anything that changes how data looks or what is shown (inversion, gamma, removed lanes, strips, marker image, densitometry method) is reported in `G.Export.legendHints` and the processing log.
- Colours in CSS are tokens on `:root` with dark values under `prefers-color-scheme` and `[data-theme]`; the values are the Paper Radar palette (teal accent, amber warn, green ok) so the owner's artifacts match. The figure itself is always black on white, and the overlay colours on the raw image (red crop, blue lanes, yellow marker, teal strips, green band boxes) are functional, not theme colours.
- Ladder additions need a manufacturer datasheet (see CONTRIBUTING.md).
- New behaviour gets a check in `js/uitest.js` (sections 20+) and an assertion in `tests/run.mjs`.

## Claude artifact

The app is published as a Claude artifact at https://claude.ai/artifact/TaJkMEbS7d2Yf81LcVr2oj (pinned in the owner's sidebar) with capabilities `{"downloads": true, "sample": {}}`.

To update it after changing the app: `npm run build`, then publish `dist/gelgrapher-artifact.html` to that URL with the Artifact tool (pass the URL as `url` from a new conversation; omit `capabilities` to keep them, omit `icon`). Things that differ inside the artifact viewer:

- downloads go through `claude.use('downloads').save()`, which only accepts png, jpg, gif, webp, svg, pdf, csv, json, txt, md, html, xlsx, docx, pptx, zip; `G.Export.download` wraps anything else (TIFF, `.gelfig`, original data) in a ZIP, and the app opens such ZIPs;
- `sample` powers "Draft legend and methods with Claude" (`js/claude.js`); it sends only a text summary, never the image;
- no query string reaches the page, so the `?demo=1` / `?uitest=1` test hooks only work on a normal server.
